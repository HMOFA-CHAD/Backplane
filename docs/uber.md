# The uberbot

One bot the person makes their main interface across all projects, machines and bots. Nothing promotes a bot by itself.

Built now (increment 1a, core only; the clients' screens come next):
- `UberSet{bot, uid, at}` (model.bend, codec.bend) folds as the settings `uber.bot` (its bot id here; "" for none) and `uber.uid` (its id across machines). It is not shared with other machines yet (far.bend leaves it out).
- `src/core/uber.bend`: `Uber.bot(st)` (the uberbot's id; "" when its bot is gone or is a mirror from another machine), `Uber.is`, `Uber.uid(now, seed)`, `Uber.promote(st, bot, uid, now)` (a `Promo`: an error text, or the changes to log; "" demotes). Only a live bot of this machine can be promoted. Laws `uber_*`.
- RPC `bots.uber {bot}`. A demotion is logged at once. A promotion first runs a server job (`BotFx "uber"`, `BotJob.uber`) that backs the bot up under `<home>/backups/uber-<now>-<bot>`: its home folder (`home/`) and the log lines that name the bot or its thread (`events.jsonl`). The log itself is never rewritten. Only when that worked does the server log `UberSet` with a fresh uid; otherwise it answers an error and logs nothing.
- The uberbot's turn prompt says so (bothub.bend's `Bots.prompt.uber`).
- Client state (client.bend, botui.bend): the uberbot is not in the bot list (`BU.rows`); `BU.uber(u)` is its row. Its tabs start with `status` (`BU.tabs.for`, `BU.tab.dflt`). Actions `uber` (select it on Status), `uber-promote <bot>`, `uber-demote`, `uber-bot <bot>|<tab>` (a bot with a tab, for a routine's row); a bot's menu (`bot-menu <id>`, kept as `b:<id>`) offers "Make uberbot" / "Not uberbot".
- Rooms seen: the setting `room.seen.<room>` (seconds). `Rooms.unread(u, room)` counts the posts after it that the person did not write; opening a room with some unread sends `setting.set` of it to now, one with none sends nothing.
- The status plane, `src/core/plane.bend`: `Plane.of(u, now)` is what the Status tab draws, for every client: need (approval, question, failed; most urgent first), run (working, queued), bots, rooms with unread, routines (running first, then the soonest due), the rest of the day's live threads (at most 50, `idle_n` the whole count), and the machines. Threads and bots on the owner's other machines are in the client's state as `<link>~<id>` and are included; a machine that does not answer shows its rows as away and asks for nothing. `Plane.key(u, now)` is cheap and changes whenever the plane can (the log's sequence, each machine's head and whether it answers, the minute), so a client builds the plane only when it changes; `Plane.counts(p)` is the sidebar row's "3 need you · 7 running". Laws `plane_*`.

Built in increment 2 (sync; `src/core/ubop.bend`, `src/core/ubersync.bend`, server.bend "The uberbot's sync"):
- One uberbot on the owner's linked machines. Each machine keeps its own replica (an ordinary local bot with its own thread, tied to the `uid` by `UberSet`). Memory, space and page, name/look/persona and routines are replicated and converge; the conversation runs on one machine at a time; machines away keep working and merge when back.
- Machine id: the setting `machine.id`, made by the hub once (`Hub.uber.ensure`, at the first tick) and never changed.
- The op log: `UberOp{uid, origin, n, stamp, op, at}` (model.bend; codec tag 58). `origin` is the machine, `n` its own count (1, 2, ...), `stamp` a hybrid logical clock `<secs 10 digits>.<counter 6 digits>.<origin>` (string order is time order; `Ub.stamp.next` never goes behind a stamp seen), `op` compact JSON (`mem`, `forget`, `space`, `page`, `who`, `routine`, `routine-del`, `fired`, `lease`, `bind`; builders `Ub.b.*`). The fold (`State.uberop`) takes an op only as its origin's next one (`n` = highest seen + 1), so what a machine has from an origin is always 1..n (an out-of-order op is dropped and comes again), and keeps, as settings under the uid: `uber.vv.<uid>.<origin>` (highest n), `uber.op.<uid>.<origin>.<n>` (the line, for sending on), `uber.r.<uid>.<key>` + `uber.rs...` (the register: op and stamp, kept only if later; keys `mem:<key>` (a forget is a tombstone in the same register), `space`, `page`, `who`, `routine:<gid>`, `lease`, `bind:<machine>`), `uber.fired.<uid>.<gid>` (highest slot run, `uber.firedby` who ran it), `uber.origins.<uid>` (sorted), `uber.hlc.<uid>`. The lease register is ordered by term first, then stamp. Keyed by uid so a new uberbot starts clean.
- `Ub.derive(st, op)` is what a taken op that wins does to the replica (MemorySaved, MemoryForgot, SpaceSet, SpacePageSet, BotSet, RoutineSet, RoutineDeleted, RoutineFired); nothing when it loses, and never an op (law `uber_derived_no_ops`). `Ub.commit(lines, st)` takes op lines in order and returns the changes to log (the ops, their derived changes, and an activity line in the uberbot's thread when a routine ran for a slot another machine already ran).
- Making ops: `Ub.also(st, now, changes)` adds the ops for what the uberbot's own tools and clients changed (memory, space, page, name/look/persona, routines); `Bots.hub`, `Bots.mcp` and the routine tick call it (`Bots.ub`). Changes derived from another machine's ops do not go through it. `Ub.init` logs the first ops of a promoted bot (its name and look, memories, space, page, routines, lease term 1, `bind`), after the server logs `UberSet` (`UberDo "init"`).
- Sync: `uber.sync` over the signed `POST /far/rpc` (owner's machines only, `Far.own.id`). Both ways carry `{uid, machine, name, vv, ops, beat, offer}`; the answer has the same shape (the asker's `vv` says which ops come back; at most 64 per origin per exchange, `Ub.batch`, and more rounds while either side still lacks). A request goes to each owner link after any step that logged an op (`Uber.after`) and on the minute tick (anti-entropy); one is out per link at a time, a wanted one waits (`busy.<link>`, `again.<link>` in `FR.Fh.ub`, the hub's memory, not the log). The holder also sends one every 15 s, its heartbeat.
- The offer: a machine with an uberbot offers it (`{uid, name, look}`); a machine with none keeps it as the setting `uber.offer` (JSON `{uid, name, look, machine, link}`; a setting, not info, so all four clients read it from their state; `Ub.offer(st)`). RPC `bots.uber_join {uid}` (only for the offered uid; refused when this machine has an uberbot, or a bot of that name) makes the replica bot, ties it to the uid, clears the offer and logs its `bind`; the first exchange fills it from the others' ops.
- Hiding the mirror: the other machines' replicas arrive as far bots `<link>~<bot>` and in the machines' bot lists; `Ub.far(st)` lists the former (from `bind` ops and the setting `uber.link.<uid>.<machine>` logged when an exchange first arrives over a link), `Ub.far.named` the latter, and `BU.rows` leaves both out (so the Status plane's bots do too). Computed from the client's own state; nothing is sent.
- The conversation: the lease register is `{holder, term}`. `Ub.chat(st)` is the thread the Chat tab shows: the replica's own while this machine holds the lease, else the holder's thread as mirrored here (`<link>~<thread>`); `Bots.select` uses it for the uberbot and `Bots.chat.is` keeps the bot's view up on any of its threads. A holder that learns of a higher term stops firing routines and heartbeats (`Ub.holder.me`, `Ub.beat`).
- Takeover: on the minute tick, a machine that has the uberbot, does not hold the lease, has not heard the holder's beat for `Ub.grace()` seconds (600; `BACKPLANE_UBER_GRACE` overrides, for tests; a hub counts from its start) and is first of the machines it can reach (machine ids sorted, the holder left out; `Ub.first`, `Ub.reach`) logs `lease{me, term + 1}` (`Ub.takeover.cs`). Two machines taking the same term end with one holder (the later stamp). The old holder's last 20 entries, from its mirror (`Xref.handoff`), are queued ahead of the new holder's next message (`<handoff>`, like a fork's context).
- Routines: `Bots.tick` runs an uberbot routine only where `Ub.fires(st, gid, slot)`: a pinned one (`bots.pin {routine, pin}`; "here" for this machine, "" to unpin) only on its machine, any other only on the holder, and a slot (the scheduled time, `Cron.next`) only once; the run logs a `fired` op, which marks the routine fired on the others. Unpinned is at least once across a partition (both sides may fire; the duplicate is logged when the ops meet: `Ub.dup`); pinned is at most once.
- Laws `uber_merge_comm`, `uber_merge_idem`, `uber_forget_wins_older`, `uber_forget_loses_newer`, `uber_one_holder_per_term`, `uber_higher_term_wins`, `uber_fire_holder_only`, `uber_pinned_stays`, `uber_slot_once` (general, over `Ub.fires.k`), `uber_fire_state*`, `uber_slot_once_state`, `uber_pinned_state`, `uber_derive_n_no_ops`, `uber_derived_no_ops` (general); the merge laws are over concrete ops. Tests `test/uber_sync_test.bend`, `bun test/tools/uber_e2e.ts`.

Not built:
- Compaction of the op log (every page revision stays in `uber.op.*`).
- A routine's schedule is read in each machine's own time zone; machines in different zones compute different slots for the same routine.
- Room pickers still list another machine's replica by name.
