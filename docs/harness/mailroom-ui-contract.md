# Mailroom UI over the Bend service

The authenticated `/ws` connection carries existing CBOR `{id:number,m:string,p:object}` RPCs; use the service wire dictionary/codec rather than JSON text frames. Responses are `{t:"reply",id,ok,result? ,error?}`. Do not use MCP to implement the human UI. Pair/authenticate normally; renderer capability is not authorization.

`mail.on` currently gates both mailbox RPCs and automation in source45328/binarybf4. That is a concrete blocker while live mail is OFF. The additive quiet-UI patch lets only the existing human RPC dispatcher access the mailbox independently. It does not activate MCP mail tools, inbound tees, hidden run routing, restart recovery, disposition grants or notifications. The old service needs the successor before the UI can claim this separation.

- `mail.list`: `{bot, status:""|"unread"|"open"|"done"|"snoozed",project:"",skip:0,n:50}` -> `{convs:[row],total}`. `bot` is a raw bot ID, `thread:<id>`, or `*` for the aggregate; use real per-owner scope for read marks. Rows contain `id,subject,kind,parts,project,tags,last,n,status,unread,head,from`. ACT/FYI are message intent (`MailPosted.want`/body `want`), not accepted conversation-status filters on this service. Do not pass `status:"act"` or `"fyi"` and interpret empty results as an empty mailbox.
- `mail.find`: `{bot,q,n:50}` -> same list shape. Correlate the full query/hub/owner request and ignore stale responses. This searches existing indexed header material; do not claim full body search.
- `mail.read`: `{conv,bot,before:"",n:50}` -> `{conv:row,mails:[{id,from,to,kind,want,at,text}],more}`. Wire messages are newest first. To fetch older history use the LAST/oldest returned raw mail ID as `before`. Render chronological order if desired; retain full text/UTF-8, no truncation oracle. An explicit nonempty `bot` records that receiver's open/read mark. Empty bot is a nonmarking body fetch; opening aggregate scope is not a substitute for reading as a receiver.
- `mail.mark`: `{bot,conv,status,until?:epochSeconds}`; accepted status is `unread|open|snoozed|done`. These mark a mailbox conversation, not a project objective.
- `mail.tag`: `{bot,conv,tags:[string]}`.
- `mail.send`: `{to:"bot:<rawID>"|"thread:<rawID>",conv,subject,text,want:"act"|"fyi"}`. Preserve opaque IDs including `|`; never split them as machine delimiters. An explicit worker send keeps ordinary thread delivery. A bot-target send is filed only while automation is OFF: say "Filed; automation paused", never "processed". No hidden bot wake or direct FOH post is allowed in that case.

A send RPC success is acknowledgment, not proof of durable filing/delivery. Match the subsequent committed `MailPosted` header and owning conversation/body echo before claiming filing. Preserve the captured draft and newer edits across delayed ACK/error/disconnect; unknown outcome is not permission to resend. No retry loops or reconnect replay. Existing server body append/header commit dedup is by mail ID; a fresh send RPC creates a fresh ID and is not cross-session idempotency.

Maintain hub + origin + owner + opaque conversation identity; clear stale results on switch/reset. Body/list pages are bounded by `n` (maximum200). Push journal changes update headers/marks; avoid full-history/settings scans or per-frame RPC polling. Expose actual errors rather than showing an empty inbox on `mail is off`.

Quiet rollout: root alone installs the successor and controls settings. Keep live mail.on OFF. Do not reenable automation to unblock reading, replay historical wakes, resend old notices, or infer a performance/release waiver. Existing 294682/295241/295424 qualified service receipts remain preserved; no provider replay is needed for this patch. Focused successor acceptance must establish OFF-state UI read/mark/filing plus zero hidden RunSet/FOH posts, authenticated/unauthenticated boundary and unchanged OFF MCP refusal.

For later root-authorized automation activation: direct bot FYI files only; actionable mail creates or joins at most one live run per bot/conversation, after durable fresh-header commit. Room FYI with an explicit bot mention is an existing exception that can act. Receipt/reply/escalation disposition suppresses only the exact current input, never a newer message. Unresolved completion reports once per current-input token. The only automatic Codex approval grant is mail_dispose on a live exact run; other reviewed product/external/shell actions remain restricted. Root must qualify old pending-run recovery separately before enabling startup continuation; no backlog replay is authorized here.
